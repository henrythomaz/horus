Backend e Rede Neural do Horus
Objetivo

Este documento define o plano de desenvolvimento da parte de Backend e Inteligência Artificial do Horus durante os próximos 15 dias.

O desenvolvimento será feito em uma ordem incremental:

Criar e validar o MVP da rede neural.
Garantir que o modelo consiga realizar inferências.
Estruturar o banco de dados.
Integrar o modelo ao banco.
Criar a API.
Integrar imagens, missões e detecções.
Implementar georreferenciamento e cálculo de risco.
Integrar tudo em um backend funcional.

A prioridade é não construir infraestrutura em cima de uma IA que ainda não foi validada.

Dataset

O projeto utilizará inicialmente o dataset:

Aedes Mosquito Breeding Habitat Detection

O dataset está disponibilizado em formato YOLOv8 e possui:

train/
valid/
test/

Com as classes:

coconut_shell
drum
other_containers
tire
water_tank

O dataset possui aproximadamente 2.821 imagens.

As imagens já possuem suas respectivas anotações .txt no formato YOLO.

Portanto, não será necessário recriar as anotações inicialmente.

Dia 6 — Criar o banco de dados

Agora que o comportamento básico da IA está definido, começar o PostgreSQL.

Implementar o DER já definido para o projeto.

As principais entidades serão:

organizations
users
missions
images
detections
detection_classes
risk_areas
reports

A estrutura deve representar o que realmente acontece durante uma missão.

Uma missão começa quando uma organização solicita o monitoramento de determinada região.

O drone captura imagens.

As imagens são processadas.

A IA produz detecções.

As detecções podem gerar áreas de risco.

Dia 7 — Relacionar o banco com o dataset e as detecções

Criar a estrutura responsável por representar no banco aquilo que o modelo produz.

Uma imagem poderá possuir várias detecções:

images
   │
   └── detections
          │
          └── detection_classes

Uma detecção deverá armazenar informações como:

id
image_id
class_id
confidence
x
y
width
height

A classe representa o objeto detectado:

coconut_shell
drum
other_containers
tire
water_tank

O banco não precisa armazenar o .txt do dataset como texto bruto.

Ele deve armazenar os dados resultantes da interpretação da anotação/detecção.

Dia 8 — Criar o pipeline de inferência

Criar um módulo Python responsável por:

imagem
   ↓
YOLO
   ↓
detecções
   ↓
resultado estruturado

Por exemplo:

[
    {
        "class": "water_tank",
        "confidence": 0.91,
        "bbox": [...]
    }
]

Esse módulo será utilizado posteriormente pela API.

O objetivo é separar:

IA

de:

HTTP/API

Assim, o FastAPI não precisa conhecer os detalhes internos do treinamento.

Dia 13 — Sistema de risco

Criar a primeira versão do cálculo de risco.

container       → peso W
